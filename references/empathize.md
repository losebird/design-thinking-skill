# 共情 Empathize

目标：放下自己的经验与判断，像“刚来到地球的外星人”一样好奇地观察和提问，弄清**谁是用户、他们在什么情境下、想完成什么任务、被什么卡住**。
产物：AEIOU 观察记录、访谈提纲与记录、用户画像、移情图、顾客旅程图、（可选）Hook 分析、竞品分析、极端/未来用户清单。

## 1. 核心工作
1. **理解与观察**：定量数据（人群规模、人口统计）+ AEIOU 现场观察（真实世界与数字世界都要看）。
2. **提出假设 → 确认假设**：先描述相似特征的用户群，再用数据和移情图支持或修正。
3. **找出模式**：最初的用户分群还成立吗？有没有被忽略的重要群体？用 JTBD 理解“他们为什么买/用”。
4. **持续完善画像**：每次访谈、照片、原话、故事都会让画像更清晰。
5. **深挖需求**：访谈、亲身体验用户的一天（例如去养老院做义工、模拟视力受损者）、访谈极端用户、反思自己的提问方式。

## 2. 访谈技巧（→ `tables.interview`）
- 问开放式问题，不引导、不假设；让对方讲**具体的一次经历**（“上周加班最晚那天……”）。
- 多问“为什么”，追到动机层。
- 要**具体事例**，让对话聚焦；问**例外**：“什么时候它不起作用？”——找到问题边界。
- 记录原话、情绪、肢体语言、语气；区分“对方说的”和“你推断的”。
- 对含糊词追问含义（用户说“资源”，指的是什么？）。
- 用 WH 问题（谁/什么/何时/何地/为什么/如何）检查覆盖面。
- 团队讨论时用“发言棒”：拿着的人说，其他人只听，保证每个人被听见；保持专注（正念）有助于感知细节。
- 用户提出的“我想要功能 X”只是他对问题的猜测解法，要追问：“没有 X 时，你真正困扰的是什么？”

## 3. AEIOU（→ `boards.aeiou`）
| 维度 | 看什么 |
|---|---|
| A 活动 | 发生了什么？用户在完成什么任务？之前、之后做了什么？ |
| E 环境 | 物理与社会环境、空间特性、限制与机会 |
| I 互动 | 人与人、人与物的互动；频率、时长、障碍与促进因素 |
| O 物体 | 用到的物品、设备、工具；其设计如何影响体验 |
| U 用户 | 有哪些人、角色、谁影响他们、动机、偏好 |
只记事实；推断另行标注为“推断”。

## 4. 用户画像 Persona（→ `persona.html`，数据 `personas`）
Persona 是基于调研数据构建、代表某一用户群的**虚构典型人物**，要真实到让团队脱口而出“这不就是小王嘛”。

**构建 10 步**（`personaSteps` 记录完成情况）：
1. 找到用户：谁？多少？做什么？（定量数据 + AEIOU）
2. 提出假设：用户之间有何差异？按相似特征分群。
3. 确认：有证据支持吗？（数据 + 移情图）
4. 找出模式：原分群仍适用吗？有无新群体？（分类 + JTBD）
5. 创建画像：综合信息并具体描绘。
6. 定义情境：有哪些用例、处在什么环境？（画像画布、旅程图）
7. 检验：“你认识这样的人吗？”请熟悉该群体的人评审。
8. 传播：海报、会议、视频等方式让全队记住。
9. 创建场景：在给定背景与目标下使用产品时会发生什么？可用 Hook 模型分析习惯。
10. 持续演进：有新信息就重画；颠覆式创新可推演“未来用户”。

**画像画布 8 要素**：头像+名字 / 基本信息快照（年龄、城市、职业、收入、家庭，一张名片的量）/ 3–5 个标签 / 目标与需求（第一人称“我想……”，分功能型、情感型、社交型）/ 2–4 个痛点（“现有方案让我……”）/ 典型行为与场景（一天时间线，越具体越好）/ 动机与价值取向（行为背后的 WHY）/ 一句带情绪的代表性引言。

要点：用真实感的姓名与特征；尽量视觉化（海报、真人大小）；放进具体情境；聚焦产品能支持的“待完成任务”；一轮轮迭代。之后任何人想加功能，先问一句“这对 TA 有用吗？”

## 5. 移情图 Empathy Map（→ `empathy-map.html`，数据 `empathyMap`）
六区：**看 Sees、听 Hears、说 Says、做 Does、想 Thinks、感受 Feels**，外加**痛点 Pains** 与**收获 Gains**。简化版只用说/做/想/感受四区（看与听常常可从“说”中获得）。
> 勘误：部分资料把“看”误标为 Says，正确对应是“看 Sees”。

移情图的价值不在“抄录用户说了什么”，而在**拆开、对照、验证**：
1. **区分信息来源**：说（理性、社会化表达）/ 想（更接近真实动机，常需推断）/ 做（最可信的行为证据）/ 感受（情绪驱动）。每张卡片标注证据类型：原话 quote / 观察 observed / 推断 inferred / 假设 assumed。
2. **不直接采信用户给出的解决方案**，往回追问题本身。
3. **放进情境**：同一个人在不同时间、压力、环境下行为不同。
4. **用行为验证**：点击路径、放弃点、犹豫时长比访谈更接近真相。

洞察来自“说 vs 做 vs 想”的**矛盾**（`contradictions`）。例：用户说“注重健康、想自己做饭”，行为却是常点外卖、加购后放弃——真正的阻碍是“怕买错、不会做、浪费钱”（决策焦虑 + 失败成本），方向就从“增加高端食材”变成“一周菜谱包 + 超简单做法 + 小份量”。
每张移情图应产出一句核心洞察（`coreInsight`）和一份待验证清单（`toVerify`）。

## 6. 顾客旅程图（→ `journey.html`，数据 `journey`）
按阶段记录：行为、触点、想法、情绪（-2 到 +2）、痛点、机会点。情绪低谷就是最值得切入的机会。旅程图要绑定一个画像和一个具体场景。

## 7. Hook 上瘾模型（→ `hook.html`，数据 `hook`）
来自 Nir Eyal《上瘾》。闭环四步：
1. **触发**：外部触发（推送、红点、链接）；内部触发（与情绪绑定，如无聊、焦虑、饥饿）——让产品成为某种情绪的“解药”。
2. **行动**：期待酬赏的最小行为。Fogg 行为模型 B = MAT（动机 × 能力 × 触发）；降低门槛往往比激发动机更有效。
3. **多变的酬赏**：社交酬赏（被认可）、猎物酬赏（资源、信息）、自我酬赏（掌控感、完成感）；不可预测性维持兴趣。
4. **投入**：用户投入数据、时间、社交资本后，产品下一轮更好用，并为下次触发埋下伏笔。

**伦理**：问两件事——它是否实质改善用户生活？你自己是否会长期使用？得到“赋能者 / 娱乐者 / 推销者 / 操纵者”四象限，**拒绝操纵者设计**。Hook 常用于构思与原型阶段；在共情阶段可用它构建画像场景、挖掘真实痛点。

## 8. 极端用户与未来用户（→ `tables.extremes`）
- **极端用户**：在某方面需求特别强或行为特别突出（例如高龄仍做剧烈运动的老人），往往提前暴露主流用户未来的隐性需求。
- **领先/未来用户**：已经以“明天的方式”生活的人；对颠覆式项目，推演未来人物的价值观、生活方式、科技习惯如何变化。
- 也可以访谈“非用户”：他们为什么不用？

## 9. 竞品与替代方案（→ `tables.competitors`）
包括直接竞品、间接替代、以及“什么都不做”。从 JTBD 角度看竞争：Netflix 的对手可能是“睡眠”和“一杯红酒”。

## 10. 桌面研究（二手资料，→ `deskResearch.query`、`deskResearch.sources`）
进入陌生领域、或用户只有一个模糊问题时，先用公开资料缩小问题：「研究问题拆解」把问题拆成 4–6 个可检索的子问题和关键词矩阵，「来源管理板」逐条记录来源与可信度。桌面研究回答“有多大、谁在做、有什么约束”，回答不了“为什么、怎么感受”——后者仍要靠访谈与观察。详见 `desk-research.md`。

## 11. 待真人验证
AI 生成的画像、移情图、旅程图都是**假设**。每份产物都要附 `toVerify`：去哪里观察、问谁、问什么、用什么行为数据验证。

## 12. 用户研究计划（→ `research-plan.html`，数据 `researchPlan`）
**在访谈 / 问卷开始前**制定，确保每轮研究都有清晰目标和可验证的假设。测试阶段也可复用本工具制定测试脚本。

包含五个部分：
1. **假设清单**（`hypotheses`）：本轮研究要验证的假设，标注风险等级（H/M/L）和是否本轮验证（`selected:true`）。
2. **招募方案**（`recruit`）：受访人数、访谈模式（remote/inperson/diary/usability）、筛选标准（至少 1 条 include + 1 条 exclude）。
3. **访谈脚本**（`script`）：分三段——暖场（`warmup`）、核心问题（`main`，至少 3 条开放式）、收尾（`wrap`）。避免封闭式问题（yes/no）。
4. **分析框架**（`analysis.fw`）：affinity（亲和图聚类）/ metrics（量化指标对比）/ insights（提炼核心洞察）三选一。
5. **进度追踪**（`progress`）：已完成/进行中的访谈数量与状态。

质量要求：每条假设必须可证伪（能被"证实"或"证伪"，而非价值判断）；脚本问题以"你上次……"开头的情境式问题为最优。
