# AI 辅助设计思维：各阶段提示词与工具

人与 AI 是“结对工作”的伙伴：AI 负责数据密集、生成密集的工作（知识放大、整理、生成选项），人负责共情、判断与战略。**AI 产出一律是假设**，需要真人验证。

| 阶段 | AI 核心能力 | 主要益处 |
|---|---|---|
| 共情 | 知识放大 | 效率与速度、深度洞察 |
| 定义视角 | 洞察提炼 | 深度洞察、准确性 |
| 构思 | 创意生成 | 丰富性、打破常规 |
| 原型 | 具象加速 | 加速迭代、节省时间 |
| 测试 | 效果优化 | 准确性、数据驱动决策 |
| 反思 | 流程自省 | 持续学习、自我优化 |

> 作为 agent 执行这些提示时：把结果写进项目 JSON 对应字段，渲染成交互页面，并附上 `toVerify`。下面的 `{}` 是需要替换的内容。

## 共情
**访谈记录**：用录音转写工具（如 ima 笔记、钉钉 AI 听记、飞书/腾讯会议纪要）。把转写稿交给 agent 整理。

**问卷（AEIOU）**
```
请为「{项目}」生成一份调查问卷，重点了解用户身份（{如：上班族、上下班时间}）、{关键行为}习惯、对{核心价值}的期望、对{技术/渠道}的接受度。遵循设计思维的同理心原则，按 AEIOU（活动、环境、互动、物体、用户）五个维度设计问题；以开放式和具体经历类问题为主，避免引导性问题。
```

**访谈提纲** → `tables.interview`
```
请为「{项目}」的用户访谈写一份提纲：开场、背景、具体经历、深挖、例外、收尾。每个问题附 1–2 个追问（为什么/能举个例子吗/什么时候不是这样），并写明想了解什么。
```

**次级调研 / 竞品**（深度研究工具，如秘塔、各家 Deep Research、NotebookLM、Notion AI）→ `tables.competitors`
```
请调研国内市场上与「{项目}」相关的竞品与替代方案：服务商、产品特点、运营情况、用户评价。按“直接竞品 / 间接替代 / 不作为”分类，并指出用户为什么选择或放弃它们、存在哪些机会空白。请给出信息来源。
```

**移情图** → `empathyMap`
```
请根据以下访谈记录生成移情图：看、听、说、做、想、感受，以及痛点与收获。每条标注证据类型（原话/观察/推断/假设），找出“说 vs 做 vs 想”之间的矛盾，并据此写一句核心洞察和待验证清单。
{访谈记录}
```

**用户画像** → `personas`
```
请根据以下调研资料构建 {2–3} 个用户画像，每个包含：头像与名字、基本信息快照、3–5 个标签、目标与需求（第一人称，分功能/情感/社交）、2–4 个痛点、一天中的典型行为时间线、动机、一句代表性引言，以及一段可用于生图工具的画像提示词。
```
（画像卡片配图可用 Gemini、Midjourney 等生图工具，把 `imagePrompt` 交给它们，生成后把图片地址填回 `image`。）

## 定义视角
```
请基于以下洞察：1) 选出最重要的约 10 条并投票排序；2) 用 JTBD 句式写出核心任务（当…时，我想要…，这样我就能…），区分功能/情感/社会任务；3) 写出 3 种 PoV 句子（标准 d.school、用户故事、用户故事+痛点）；4) 导出 5 个“我们可以如何……”问题。注意：需求中不要出现具体解决方案，洞察要解释“为什么”。
```
用户故事示例：作为一名经常很晚下班、很疲惫的上班族，我想要到家就有一口热食，以便图个温暖和方便。

## 构思
**SCAMPER** → `ideate.scamper`
```
请根据竞品分析与 HMW「{问题}」，用 SCAMPER 为「{项目}」生成创新点子：替代、结合、适应、修改、用作他用、去除、重组（Rearrange），每个角度 3–5 个，越具体越好。
```
**其他**：问题反转（“怎样让问题更糟？”再反转）、跨行业对标、头脑风暴种子点子。AI 给选项，人来筛选、组合、优化。

**收敛** → `ideate.matrix`
```
请把以下点子按「价值 × 可行性」（或「影响 × 紧迫」）各打 1–5 分，说明评分依据与关键假设，标出落在边界附近需要再讨论的项。
```

## 原型
- **文本 → 线框**：`请把以下用户故事转成低保真线框与交互流程，用 Markdown + Mermaid 表示每个页面的结构和跳转。`
- **可运行原型**：作为 agent，可直接写单文件 HTML 可点击原型；或使用 v0、Bolt、Cursor、Copilot；Agent/工作流原型用 Coze、Dify、n8n。
- **视觉稿**：Figma、Lovart、Uizard 等。
- **服务原型**：`请为「{方案}」生成服务蓝图：步骤、用户行为、前台触点、后台活动、支持系统、有形证据、失败点。` → `tables.blueprint`
- **MVP**：先问“验证核心假设的最小东西是什么？”（演示视频、落地页、人工假装自动化……）

## 测试
```
请为「{原型}」设计一轮用户测试：要验证的假设、测试场景、开放式问题地图、主持人/演员/观察者分工、预测试安排，以及成功标准。
```
```
以下是 {n} 位用户的测试记录，请按“喜欢 / 期望 / 问题 / 新点子”整理，归纳主要发现，并给出“保留 / 迭代 / 放弃”建议。
```
A/B 数据：把两组样本与转化数填入 `test.ab`，由页面计算显著性，agent 负责解读与给出下一步。可以考虑为团队搭一个专门的“测试 Agent”。

## 反思
```
请根据本轮的测试结论、试验表和团队反馈，起草一份回溯板：做得好的、可以改进的、问题/困惑、下一步行动（每项含负责人与时间建议）。
```
