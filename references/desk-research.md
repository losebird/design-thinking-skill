# AI 辅助桌面研究（Desk Research）

桌面研究是**二手研究**：利用已经存在的公开资料（官方统计、行业报告、企业财报、学术论文、媒体报道、社区讨论）回答问题。它与一手研究（访谈、观察、问卷、测试，见 `research-plan.html` 与 `references/test.md`）互补：

| | 桌面研究（二手） | 用户研究（一手） |
|---|---|---|
| 回答 | 有多大、谁在做、趋势如何、有什么约束 | 为什么、怎么感受、在什么情境下 |
| 证据 | 来源 + 可信度 | 原话、观察、行为数据 |
| 速度 | 快（小时 ~ 天） | 慢（天 ~ 周） |
| 风险 | 过时、口径不符、营销稿、AI 编造 | 样本小、引导性提问 |

**原则：桌面研究负责“缩小问题、找到空白”，一手研究负责“理解人、验证假设”。** 不要用桌面研究的结论代替与真实用户的接触。

## 1. 五个工具与使用时机

| 顺序 | 工具 | 页面 | 数据路径 | 阶段 | 何时用 |
|---|---|---|---|---|---|
| 1 | 研究问题拆解 | `research-query.html` | `deskResearch.query` | 共情 | 进入陌生领域、项目启动，或用户只有一个模糊问题时 |
| 2 | 来源管理板 | `source-board.html` | `deskResearch.sources` | 共情 | 检索资料时边读边记；评估每条来源的可信度与相关性 |
| 3 | 综合矩阵 | `synthesis.html` | `deskResearch.synthesis` | 定义 | 来源达到 6 条以上，需要提炼共识 / 分歧 / 不确定时 |
| 4 | 研究空白 | `gap-analysis.html` | `deskResearch.gaps` | 定义 | 桌面研究收尾，决定还缺什么、哪些交给一手研究 |
| 5 | 研究报告 | `research-report.html` | `deskResearch.report` | 定义 | 向团队同步结论；作为画像、PoV、研究计划的输入 |

典型路径：研究问题拆解 → 来源管理板 → 综合矩阵 → 研究空白 →（一手研究：用户研究计划 / 访谈提纲）→ 研究报告 → 画像、移情图、PoV。也可以只用其中一两个工具，例如只做来源管理板给竞品分析提供依据。

每个页面底部都有 **AI 辅助** 面板：
- **✨ 让 AI 填充**：复制一段带项目上下文与 JSON 格式要求的 prompt，用于生成该工具的数据。
- **🔍 质量审查**：复制一段审查 prompt，检查来源可信度、论证是否有据、是否混入一手数据。

## 2. Agent 操作指引

### 2.1 研究问题拆解 `deskResearch.query`
1. `question` 写成“对象 + 范围 + 想知道什么”，从 `meta.challenge` 推出，不要夹带方案。
2. 拆 4–6 个 MECE 子问题（`subQuestions[]`：`id` / `text` / `why` / `angle`），覆盖市场、用户、竞品 / 替代、趋势 / 技术、政策 / 标准中相关的方面。每个都必须能靠公开资料回答；需要访谈才能回答的放进用户研究计划。
3. `keywords[]` 每个子问题一行：`subId` 指向子问题，`zh` / `en` 用逗号分隔同义词、行业术语和英文表达，`where` 写推荐信息源。

### 2.2 来源管理板 `deskResearch.sources`
1. 有联网 / 检索工具时，按子问题实际检索，每个子问题 2–3 条；优先官方统计、行业报告、财报、论文。
2. **不能联网时绝不编造 URL、机构名、报告名或数字**：`url` 留空，`summary` 写“待检索：建议搜索 …”，`status` 设为 `inbox`，并告诉用户这些需要人工检索。
3. 每条写 `summary`（关键事实 + 口径：时间、地区、样本）、`credibility` 1–5、`relevance` 1–5、`type`、`date`、`tags`。`id` 用 `S1`、`S2`… 便于引用。
4. 可信度参考 CRAAP：时效（Currency）、相关（Relevance）、权威（Authority）、准确（Accuracy）、立场（Purpose）。

| 分数 | 典型来源 |
|---|---|
| 5 | 官方统计、法规原文、同行评审论文 |
| 4 | 知名研究机构报告、上市公司财报 |
| 3 | 主流媒体报道、企业自行发布的数据 |
| 2 | 自媒体、社区讨论（只作旁证）、二次转载 |
| 1 | 无出处观点、营销软文、有明显利益关联 |

### 2.3 综合矩阵 `deskResearch.synthesis`
- `consensus`：≥2 个**独立**来源一致（同一原始数据被多家转载只算 1 个）。
- `divergence`：来源矛盾或口径不同，`note` 写可能原因。
- `uncertain`：单一来源、数据过旧、可信度 ≤ 2 或无法核实。
- 每条 `sources` 写来源 id，只用 `status` 不是 `drop` 的来源；观点写成可被证伪的完整陈述。

### 2.4 研究空白 `deskResearch.gaps`
- `known`（带 `sources`）/ `unknown`（带 `priority` H/M/L）/ `toVerify`（带 `method`）。
- `toVerify` 会自动汇总进仪表盘和总览的「待真人验证」清单，所以要写成可执行动作：问谁、问什么、测什么。
- `actions[]` 区分 `type: desk`（继续检索）与 `primary`（一手研究）；一手研究行动要落到 `researchPlan` 或 `tables.interview`。

### 2.5 研究报告 `deskResearch.report`
- `background` → `findings`（每条带 `sources`）→ `implications`（明确是推断）→ `actions`（具体到下一个设计思维工具）。
- 页面会自动附上局限与待验证（来自 `gaps`）和被引用的参考来源，并可一键复制为 Markdown。
- 报告里的发现可以作为画像、移情图的背景，但证据类型最多标 `inferred`，不能标为 `quote` / `observed`。

### 2.6 校验
`scripts/validate.py` 会检查：id 重复 / 缺失、引用不存在的来源、`credibility` / `relevance` 超出 1–5、共识少于 2 个来源、已采纳来源缺少 URL、全部来源可信度过低；以及**有 sources 但 synthesis 为空**、**有 report 但 gaps 为空**两类流程提醒。

## 3. 常见错误

1. **AI 编造来源**：虚构报告名、链接或精确数字。没有检索结果就留空并标“待检索”，示例数据必须标注“示例数据”。
2. **来源可信度不足**：用自媒体、社区帖子或营销稿支撑结论；单一来源被写成共识。可信度 ≤ 2 的来源只能作旁证。
3. **综合时混入一手研究数据**：把访谈原话、现场观察写进综合矩阵或报告的“发现”。一手数据请放在移情图、洞察聚类、反馈收集表中，二者在报告里分开呈现。
4. **口径错配**：用全国数据推断一线城市、用几年前的数据描述现在、用平台订单代表全部需求。
5. **相关当因果**：“夜间订单增长”不等于“用户需要取餐柜”。
6. **子问题夹带方案**：如“用户需要什么样的智能柜”——这是一手研究的问题，而且预设了答案。竞品研究可以提到现有产品形态。
7. **只收集不综合**：来源越堆越多却没有结论。来源到 6–10 条就应进入综合矩阵。
8. **用桌面研究代替与用户接触**：报告完成后，`toVerify` 与 `unknown` 中的高优先级项必须进入用户研究计划。
