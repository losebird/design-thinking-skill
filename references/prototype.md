# 原型 Prototype

目标：把点子变成用户能体验、能评估的东西，**以学习为目的**，快速、低成本地拿到反馈。原型是需要被检验的假设。
产物：盒子原则、原型规划（类型 + 保真度 + 要学什么）、架子原则、原型工作坊记录、服务蓝图、实际原型（纸模型 / 角色扮演 / 可点击页面 / 代码）。

## 1. 三条原则
1. **尽早制作，越简单越好**：越简单、越快、越便宜，放弃时越不心疼。
2. **不要爱上你的原型**：随时准备彻底改变或放弃。
3. **原型即迭代**：迭代、迭代、再迭代。
另外：每个功能的附加价值都可以用原型测试；聚焦核心功能——“对用户来说最基本的功能是什么？还没考虑到什么？为什么之前没人做过？”

## 2. 原型类型（`prototype.plan.kind`）
| 值 | 类型 | 做法 |
|---|---|---|
| `physical` | 实体原型 | 铝箔、纸、硬纸板、乐高、橡皮泥、彩纸、毛绒条；例：手机 + 纸盒 = AR 眼镜 |
| `service` | 服务原型 | 角色扮演，模拟服务流程与触点（配合服务蓝图 `tables.blueprint`） |
| `digital` | 数字原型 | 视频、可点击演示、落地页、线框图、可运行代码 |

## 3. 保真度（`prototype.plan.fidelity`：0 低 / 1 中 / 2 高）
低保真用于初期探索；中保真用于首个解决方案；高保真用于接近最终的方案。宏观上，项目先发散（多个低保真方向）→ 转折点选定方向 → 收敛（功能原型 → 完整原型 → 最终原型/MVP），原型在“设计—制作—测试”的微观循环中逐步提高保真度。

## 4. 盒子原则（→ `box.html`，数据 `prototype.box`）
把方案当成货架上的一个产品包装盒来设计：正面写名称、标志、标语；侧面写核心益处；背面像“营养成分表”一样列出功能与属性；另有价格与企业信息。回答 5W：**谁**是目标顾客（who）、要达成**哪些**目标（which）、**何时**可用（when）、**何地**使用（where）、**为什么**要用（why）。
盒子可以是：问题盒子、解决方案盒子、项目盒子、流程盒子。它逼迫团队用最少的字说清价值。

## 5. 架子原则（→ `boards.shelf`）
把所有产品、服务、解决方案放到不同货架上（产品架、服务架、解决方案架），看组合里的**空白**与**协同**。

## 6. 原型工作坊（→ `boards.workshop`，带时间盒与步骤）
定义要测试的功能 → 构思变体 → 制作（时间盒子施压，材料要充足）→ 向其他小组演示 → 收集**绿色（喜欢）/ 红色（希望改进）**反馈 → 改进 → 精心准备真实用户测试。

## 7. AI 加速原型（见 `prompts.md`）
- **文本 → 线框**：用 LLM 从文字/草图/截图生成低保真线框与流程，例如在 VS Code + Copilot 中生成带 Mermaid 流程图/线框的 Markdown 设计文档。
- **生成式设计**：Figma、Lovart、Uizard 等生成可编辑的视觉稿。
- **代码生成**：Copilot、Cursor 等生成前后端代码；v0、Bolt 快速做出可运行原型；Coze、Dify、n8n 搭 Agent/工作流原型。
- **更广义的原型**：服务蓝图、旅程图；MVP 思路——Dropbox 最早的 MVP 只是一段演示视频。
- 作为 agent，你可以直接写出 HTML 可点击原型并保存为文件，让用户在浏览器里点。
