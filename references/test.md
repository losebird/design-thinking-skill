# 测试 Test

目标：在真实情境中把原型交给潜在用户，**学习**他们的真实动机与需求，验证假设对错，据此“喜欢它（保留）/ 改变它（迭代）/ 放弃它”。
产物：测试计划、反馈收集表、A/B 测试结论、试验表。

## 1. 关键要点
1. **尽早、频繁**：有草图就可以测，快速重复。
2. **千万不要爱上你的原型**。
3. **学习而非推销**：不要解释原型怎么用，更不要推销。
4. **真实用户、真实环境**：同事可以预演，但潜在用户更有启发。
5. **开放式问题**，常问“为什么”，不引导。
6. **中立**：最好由没参与制作的人主持；让被测者边做边说（出声思考），不打断。
7. **记录与分享**：照片、录像、笔记，记下如何使用与误用；反馈是礼物，感谢、倾听、不辩解。
8. **持续迭代**：早期多次失败是通往成功的正常路径。

## 2. 测试准备（→ `tables.testplan`）
- 目标与假设：这次要学什么、测什么？
- 问题地图：简单、开放、与用户真实情况相关的问题。
- 测试场景：描述被测者所处的真实情境，可准备多个简短场景。
- 预测试：正式测试前先找一个人跑一遍，排除低级错误。
- 角色分工：**主持人**（引导入场、交代背景、提问）、**演员**（服务原型中扮演角色）、**观察者**（专注记录全部行为，可录像）。

## 3. 反馈收集表（→ `boards.feedback`）
四象限：用户喜欢什么 / 用户有什么期望 / 出现了什么问题 / 有什么新点子。另一种写法：“我喜欢…… / 我期望…… / 如果…… / 好处是什么”。

## 4. A/B 测试（→ `ab-test.html`，数据 `test.ab`）
比较两个版本（落地页、价值主张、按钮……）的效果，**一次只改变一个变量**。
- 填写假设、唯一变量、指标，以及两组的样本量 `n` 与转化数 `conv`；页面在浏览器内做双侧两比例 z 检验，显示转化率、相对提升、p 值和差值置信区间。
- 开始前用页面下方的样本量估算（基线转化率 `baseline`%、最小相对提升 `mde`%、功效 `power`）定好样本量与停止条件，避免“看到显著就停”。
- A/B 只回答“哪个更好”，不回答“为什么”，要结合定性访谈。
- **不要编造测试数据**：示例数字必须明确标注为示例；真实数据由用户提供。

## 5. 试验表（→ `tables.experiments`）
每次试验记录：我们相信（假设）→ 为验证它我们将……（试验）→ 度量什么、收集哪些数据 → 成功标准 → 观察到/学到 → 结论（喜欢它·保留 / 改变它·迭代 / 放弃它 / 需要更多数据）。目标是用更少的时间与资源学习。

## 6. 数字化测试工具
SaaS 测试平台（上传多种原型、描述场景、预设开放问题、灵活选择专家/非专家社群）；内部反馈社群（员工 + 选定的外部顾客）做初步反馈。

## 7. AI 在测试中的位置
辅助设计测试计划与任务场景；辅助分析反馈、提炼洞察；生成测试报告与改进建议；解读 A/B 数据。核心仍是**真实的人类反馈**——AI 不能替代用户。
